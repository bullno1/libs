Detailed Description

Generational handles.

A handle is an index paired with a generation counter. The map hands out handles, tells whether one is still live and maps it back to an index. It owns nothing else: object storage belongs to the caller, so any layout works as long as it can be indexed, e.g: a plain array, a barray.h or a bseg.h.

Every query returns an index, or a pointer computed from a caller-provided base. A null, stale or out of range handle resolves to -1 or NULL and is never an error, including when destroyed.

A zero-initialized map is empty. A zero-initialized handle is null.

With contiguous storage:

bhandle_map_t map = { 0 };
barray(texture_t) textures = NULL;
bhandle_t h = bhandle_new(&map, NULL);
if (barray_len(textures) < bhandle_capacity(&map)) {
barray_resize(textures, bhandle_capacity(&map), NULL);
}
textures[h.index] = (texture_t){ ... };
texture_t* tex = bhandle_ptr(&map, h, textures); // NULL once destroyed
texture_t* dead = bhandle_at(textures, bhandle_destroy(&map, h));
if (dead != NULL) { texture_cleanup(dead); }

Capacity only changes in bhandle_new, bhandle_reserve, bhandle_grow and bhandle_load_begin. It doubles when growing, so checking bhandle_capacity after bhandle_new is enough to keep the object storage in sync.

Saving and loading

bhandle_save exposes the internal state and bhandle_load takes it back. The library does no I/O; the host serializes the array however it likes.

Objects saved keyed by handle can then be loaded in any order:

  • Map first: every saved handle is already live, so the object loader only needs bhandle_index. Capacity is known up front and the object storage is resized once. This is the recommended order.
  • Objects first, or the map state was never saved: the object loader calls bhandle_reserve for each handle, which grows the map as needed and is a no-op for handles that are already live.

Without the map state, the generations of slots that were free at save time are lost. A weak reference to a destroyed object can then come back to life once its slot is reused, so save the map state if the objects hold such references.

The free list is rebuilt in ascending index order on load, so the sequence of indices handed out after a load may differ from a run that never saved.

The width of a generation is part of the saved format, see BHANDLE_GEN_TYPE.

Resize to len slots and expose the generations for direct writes.

Generations up to min(old, len) are kept, new ones are zero (free). Returns NULL and does nothing if the allocator refused.

The map is inconsistent until bhandle_load_end, the only calls allowed in between are bhandle_free and bhandle_load_begin again. A host whose read fails halfway should do one of those, the same as it would for its own object storage.

bhandle_t  h,
void *  ctx 
)

Make a specific handle live and return its index.

For loading objects that were saved keyed by handle.

  • Already live with the same generation, e.g: the state was loaded with bhandle_load. Returns the index, nothing changes.
  • Slot is free or beyond capacity: grows if needed, marks the slot live with exactly h.gen, returns the index.
  • Returns -1 if h is null, the slot is live under another generation, or growing failed.
